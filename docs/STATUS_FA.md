# وضعیت واقعی راه‌اندازی SmartShelf — ۳ نوامبر ۲۰۲۶

## انجام‌شده در سورس

- معماری Vercel + بک‌اند دائمی با WebSocket برای Railway آماده شد (`Dockerfile`, `railway.json`, `requirements-cloud.txt`).
- برای دیتابیس و آپلودها مسیر Volume دائمی `/data` طراحی شد؛ بدون تنظیم Volume، اسکریپت Railway از اجرای Production جلوگیری می‌کند.
- فایل‌های ضروری `.env.example`, `.gitignore` و README به بسته برگشتند.
- تصاویر محصول از آدرس بک‌اند بارگیری می‌شوند، نه از مسیر استاتیک اشتباه Vercel.
- زمان انقضای QR ورود از توکن مدیر جدا شد: `ENTRY_TOKEN_TTL_SECONDS=30`.
- فروشگاه به صورت پیش‌فرض بسته است؛ در حالت بسته، رویداد برداشت آزمایشی سبد یا فاکتور مشتری را تغییر نمی‌دهد.
- در صورت نبود ONNX یا خطای شناسایی، موتور به `UNKNOWN` می‌رود و embedding تصادفی یا هویت قبلی را معتبر نگه نمی‌دارد.
- UID رویداد پس از ری‌استارت تکرار نمی‌شود.
- نوشتن heartbeat دوربین در دیتابیس محدود شد (تقریباً هر ۳ ثانیه).
- کوکی مدیر در Production با HTTPS به صورت Secure تنظیم می‌شود و محدودکننده نرخ، هدر IP پروکسی را در حالت `TRUST_PROXY=false` معتبر فرض نمی‌کند.
- اسکریپت خودکار تنظیم آدرس بک‌اند فرانت‌اند و بررسی read-only API عمومی اضافه شد.
- برای Windows، اسکریپت آماده‌سازی محیط و Tailscale Funnel به‌روز شد.

## آزمون‌های انجام‌شده

- `compileall` پایتون: موفق.
- `node --check` برای کدهای JS اصلی: موفق.
- اعتبار JSON تنظیمات Railway و Vercel: موفق.
- آزمون SQLite حافظه‌ای: رویداد حالت فروشگاه بسته ثبت شد، بدون تغییر سبد؛ آزمون تکرار رویداد موفق.
- آزمون JS مستقل: تصویر آپلودشده از URL بک‌اند و تصویر استاتیک از URL فرانت‌اند خوانده می‌شود؛ `?api` در صفحه ادمین نادیده گرفته می‌شود.
- یکپارچگی ساختار بسته و حذف فایل‌های محرمانه: موفق.

## هنوز انجام نشده

1. نصب/اتصال Railway یا اجرای بک‌اند روی رایانه فروشگاه و ایجاد تونل دائمی Tailscale؛ هیچ سرویس واقعی ابری در این مرحله ساخته نشده است.
2. ایجاد Volume دائمی و متغیرهای محرمانه در سرویس واقعی.
3. دریافت آدرس عمومی HTTPS بک‌اند، تنظیم `PUBLIC_BASE_URL` و `frontend/config.js`.
4. ساخت Preview کامل Vercel، تست API و WSS، سپس انتشار Production.
5. تست دوربین واقعی تبلت در نور، زاویه و شبکه فروشگاه.
6. اجرای Docker build واقعی و کل pytest؛ محیط ساخت فعلی به اینترنت پکیج‌ها دسترسی نداشت و `onnxruntime`/`zxingcpp` در آن نصب نبودند.
7. تست بار، بازبینی کامل امنیت XSS/نشست، سیاست بکاپ و ارزیابی دقیق مدل هویت محصول پیش از فعال‌سازی فروش واقعی.
