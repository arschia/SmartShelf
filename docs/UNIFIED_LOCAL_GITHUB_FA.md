# یکپارچه‌سازی نسخه محلی اصلاح‌شده و GitHub — ۱۴۰۵/۰۹/۰۱

این شاخه برای جایگزینی **هم‌زمان** بک‌اند و فرانت‌اند طراحی شده است. فایل‌های نسخه محلی قدیمی (۲۰۲۶-۱۱-۰۳) را با frontend جدید GitHub به‌صورت انتخابی مخلوط نکنید.

## معماری واحد

- تبلت `/camera/`: ویدیوی زنده WebRTC برای پیش‌نمایش مدیر؛ JPEG احرازهویت‌شده با WSS و در صورت قطع آن HTTPS برای هوش مصنوعی. WebRTC به‌تنهایی فریم پردازش نیست.
- مدیر `/shop`: سناریو را فعال می‌کند و فرمان ارسال فریم از بک‌اند به تبلت می‌رسد. اگر WebRTC برقرار نشد، پیش‌نمایش JPEG بک‌اند به‌صورت جایگزین فعال می‌شود و پردازش مستقل ادامه دارد. اگر WSS تبلت نیز قطع شد، ارسال JPEG از HTTPS و فرمان‌های شروع/توقف از polling احرازهویت‌شده `/api/camera/control` ادامه می‌یابند.
- تشخیص: اگر جایگاه با دو تصویر مرجع کالیبره شده باشد، تشخیص حضور/عدم حضور محافظه‌کارانه مانند نسخه محلی انجام می‌شود؛ در غیر این صورت مدل ONNX لازم است.
- مشتری: تغییر سبد فقط از گذار پایدار PRESENT ↔ ABSENT و پس از ورود مشتری فعال در بک‌اند ثبت و از طریق WebSocket اعلام می‌شود.
- توقف: ابتدا وضعیت سناریو در بک‌اند خاموش می‌شود؛ سپس فرمان توقف مستقل از WebRTC به تبلت ارسال می‌شود. عدم دریافت تأیید تبلت نباید باعث ثبت خرید شود.

## نصب نسخه یکسان در ویندوز

1. از `.env`، `data/`، `backups/` و پایگاه داده بکاپ بگیرید.
2. بک‌اند و وظایف اجرای خودکار قبلی را **کاملاً متوقف** کنید. بررسی کنید سرویس دیگری روی پورت ۸۰۰۰ اجرا نباشد.
3. **کل سورس همین شاخه** را در پوشه جدید استخراج کنید؛ فایل‌های `.env`، `.venv` یا دیتابیس قدیمی را کورکورانه روی آن کپی نکنید.
4. تنظیمات و دیتابیس را پس از بکاپ و با توجه به سازگاری schema منتقل کنید؛ برای تست اولیه از دیتابیس تازه استفاده کنید.
5. `INSTALL-SMARTSHELF.bat` را اجرا کنید تا وابستگی‌های Python 3.14 نصب شوند. WebRTC مرورگر به پکیج `aiortc` در بک‌اند احتیاج ندارد؛ بک‌اند فقط سیگنالینگ `/api/rtc/*` را فراهم می‌کند.
6. با `START-SMARTSHELF.bat` بک‌اند را اجرا کنید. اگر PIN تست 1234 می‌خواهید، فقط در محیط ایزوله محلی و طبق `SET-PIN-1234.bat` عمل کنید؛ این PIN برای اینترنت امن نیست.
7. از همان بک‌اند `/camera/` را روی تبلت و `/shop` را روی مدیر باز کنید. اگر فرانت‌اند Vercel جداست، آن را نیز **از همین شاخه** deploy کنید و `apiBase` را به همان بک‌اند وصل کنید.
8. تبلت را جفت کنید؛ در `/shop` کادر دقیق دور یک بطری بکشید، «مرجع با بطری» و «مرجع خالی» را ثبت و کالیبره کنید. سپس سناریو را فعال کنید.
9. شمارنده فریم `/api/admin/camera/status` باید افزایش یابد و `camera_live` در `/api/shop/status` باید true شود. فقط دیدن ویدیوی WebRTC کافی نیست.
10. مشتری وارد شود؛ بطری را بردارید/برگردانید؛ سپس توقف و شروع مجدد را آزمایش کنید.

## محدودیت‌ها و ایمنی

- **فقط یک بطری در هر ROI**؛ چند بطری یا حرکت دوربین/نور شدید باید UNKNOWN شود و خریدی ثبت نشود.
- قطع تصویر هرگز به معنی ABSENT نیست.
- اگر محصول هنگام قطع دوربین جابه‌جا شود، سیستم برای جلوگیری از خرید اشتباه نیاز به بررسی دارد.
- PIN 1234 فقط برای آزمایش محلی است؛ هرگز با Tailscale Funnel یا اینترنت عمومی استفاده نکنید.
- تست‌های CI جایگزین آزمایش با دوربین و ویندوز واقعی نیستند.

## وضعیت تست‌ها

- تست‌های فرانت‌اند، کنترل تبلت، WebRTC و تشخیص مرجع روی GitHub Actions اجرا می‌شوند.
- مجموعه تست‌های پشتیبانی‌شده بک‌اند روی Python 3.14 اجرا می‌شود.
- هشت تست قدیمی `backend/tests/test_recognition_phase7.py` به مدل تشخیص **هویت محصول** وابسته‌اند که در این نسخه عمداً غیرفعال و همراه پروژه ارائه نشده است. این تست‌ها در اجرای جامع CI کنار گذاشته شده‌اند؛ فعال‌کردن شناسایی هویت بدون مدل معتبر می‌تواند به ثبت خرید اشتباه منجر شود.
- هنوز تست سخت‌افزاری واقعی روی ویندوز و تبلت شما انجام نشده است.
