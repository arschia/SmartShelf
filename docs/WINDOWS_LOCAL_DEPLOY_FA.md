# راه‌اندازی SmartShelf روی Windows + Tailscale Funnel

این مسیر، بک‌اند و پردازش تصویر را روی کامپیوتر فروشگاه نگه می‌دارد. Vercel فقط رابط وب را ارائه می‌کند. تبلت دوربین از طریق WSS به بک‌اند محلی وصل می‌شود.

## قبل از شروع

- Windows 10 یا 11، نسخه 64-bit.
- اتصال اینترنت پایدار و برق دائمی برای کامپیوتر.
- دسترسی Administrator برای نصب Tailscale و ساخت Scheduled Task.
- Python 3.14؛ اسکریپت نصب در صورت وجود winget تلاش می‌کند آن را نصب کند.
- یک حساب Tailscale که مالک/مدیر آن بتواند Funnel را برای tailnet مجاز کند.
- کامپیوتر نباید Sleep یا Hibernate شود؛ برای دسترسی پیوسته باید روشن و آنلاین بماند.

## مرحله ۱ — استخراج بسته

ZIP را در مسیر ساده و ثابت مانند `C:\SmartShelf` استخراج کنید. از پوشه‌ای که مسیر آن شامل حروف فارسی یا فضای زیاد است استفاده نکنید.

## مرحله ۲ — نصب محلی

PowerShell را باز کنید و از پوشه پروژه اجرا کنید:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install_windows_local.ps1
```

یا روی `INSTALL-SMARTSHELF.bat` دوبار کلیک کنید.

این مرحله محیط مجازی Python، وابستگی‌های قفل‌شده، پوشه‌های داده و فایل خصوصی `.env` را ایجاد می‌کند. در اولین اجرای Production فقط یک محصول اولیه «دلستر هی‌جو هلو» و سه جایگاه ثابت ساخته می‌شود؛ جایگاه‌های دوم و سوم خالی می‌مانند. شناسایی هویت محصول تا زمان اعتبارسنجی مدل اختصاصی غیرفعال است؛ موتور دو‌مرجعی فقط حضور/خالی بودن را تعیین می‌کند. اگر PIN مدیر جدید چاپ شد، آن را فوراً در Password Manager ذخیره کنید؛ اسکریپت در اجرای بعدی آن را نمایش نمی‌دهد.

**مهم:** `.env` را برای هیچ‌کس ارسال نکنید و داخل GitHub/Vercel قرار ندهید.

## مرحله ۳ — نصب و ورود Tailscale

1. Tailscale را از [صفحه رسمی دانلود Windows](https://tailscale.com/download/windows/) نصب کنید؛ یا در PowerShell Administrator اجرا کنید:

   ```powershell
   winget install --id Tailscale.Tailscale --exact
   ```

2. برنامه Tailscale را از Start باز کنید و با حساب خود Sign in کنید.
3. مطمئن شوید دستگاه در پنل Tailscale به‌صورت Connected دیده می‌شود.
4. در صورت درخواست Tailscale برای فعال‌سازی HTTPS/Funnel، مجوز لازم را در مرورگر تأیید کنید. Funnel به MagicDNS، HTTPS certificates و مجوز Funnel در policy شبکه نیاز دارد.

## مرحله ۴ — اجرای بک‌اند

در پنجره PowerShell پروژه اجرا کنید:

```powershell
.\scripts\start_backend.ps1
```

پنجره را نبندید. سرور فقط روی `127.0.0.1:8000` گوش می‌دهد؛ این عمدی است. پورت 8000 را روی مودم، روتر یا Windows Firewall به اینترنت باز نکنید.

در پنجره دوم تست کنید:

```powershell
.\scripts\check_local_backend.ps1
```

باید HTTP 200 و `status=ok` دریافت کنید و Listener فقط روی Loopback باشد.

## مرحله ۵ — فعال‌سازی Funnel دائمی

در PowerShell با دسترسی Administrator و پس از اجرای بک‌اند:

```powershell
.\scripts\enable_tailscale_funnel.ps1
```

اسکریپت `tailscale funnel --bg 8000` را اجرا می‌کند، URL واقعی `https://<device>.<tailnet>.ts.net` را دریافت می‌کند و آن را در `.env` و `frontend/config.js` محلی می‌نویسد. اگر مجوز Funnel هنوز فعال نشده باشد، صفحه تأیید Tailscale را تکمیل کنید و اسکریپت را دوباره اجرا کنید.

گزینه `--bg` باعث می‌شود پیکربندی Funnel بعد از reboot یا restart سرویس Tailscale ادامه پیدا کند. خود بک‌اند نیز باید بعد از ورود کاربر Windows اجرا شود؛ مرحله بعد آن را تنظیم می‌کند.

## مرحله ۶ — شروع خودکار بک‌اند پس از ورود Windows

PowerShell را با دسترسی Administrator باز کنید و اجرا کنید:

```powershell
.\scripts\register_autostart.ps1
```

این کار یک Scheduled Task می‌سازد تا پس از Sign in همین حساب Windows، بک‌اند را در پس‌زمینه اجرا کند. بعد از روشن شدن دستگاه باید این حساب Windows وارد شود. برای اجرای خودکار بدون ورود کاربر، باید بعداً روش اجرای سرویس را جداگانه تنظیم کنیم؛ رمز حساب Windows را داخل اسکریپت قرار ندهید.

## مرحله ۷ — تنظیم برق

در Windows به مسیر Settings → System → Power بروید و Sleep را در حالت Plugged in روی Never قرار دهید. خاموش شدن نمایشگر اشکالی ندارد؛ Sleep/Hibernate باعث قطع سرویس می‌شود.

## مرحله ۸ — اتصال Frontend و دستگاه‌ها

پس از ساخت Funnel، آدرس عمومی در فایل محلی `frontend/config.js` تنظیم می‌شود. این تغییر به‌تنهایی نسخه Vercel را تغییر نمی‌دهد.

- اگر نسخه فعلی Vercel تنظیمات اتصال سرور را نمایش می‌دهد، URL Funnel را در تنظیمات سرور مرورگر Admin و تبلت ذخیره کنید.
- در غیر این صورت، باید فقط پوشه `frontend/` با `config.js` جدید به Preview پروژه Vercel با نام `shelf` منتشر شود و پس از آزمایش، به Production ارتقا یابد. در صورت استفاده از دکمه «تنظیم سرور» در پنل Admin و صفحه Camera، آدرس Funnel را در هر مرورگر جداگانه ذخیره کنید؛ این روش بدون انتشار مجدد Vercel هم قابل استفاده است.
- آدرس نهایی رابط وب: `https://shelf-ir.vercel.app`
- مسیر پنل: `/admin/`
- مسیر دوربین تبلت: `/camera/`

## مرحله ۹ — آزمون‌های الزامی

1. `https://<Funnel-URL>/api/health` باید `status=ok` بدهد.
2. `/api/admin/auth/check` بدون توکن باید HTTP 401 بدهد.
3. `/api/presence` بدون توکن باید HTTP 401 بدهد.
4. هدر CORS باید فقط مبدأ `https://shelf-ir.vercel.app` را مجاز کند.
5. تبلت با کد جفت‌سازی یک‌بارمصرف وصل شود و WSS برقرار بماند؛ پشتیبانی و پایداری WebSocket باید با اتصال واقعی تبلت تأیید شود و صرف ایجاد Funnel به‌تنهایی این آزمون را پاس نمی‌کند.
6. دوربین را در زاویه و نور واقعی قفسه آزمایش کنید؛ وضعیت باید فقط `PRESENT`، `ABSENT` یا `UNKNOWN` باشد.
7. در حالت فروشگاه بسته، برداشت آزمایشی نباید سبد خرید یا فاکتور واقعی ایجاد کند.

## مسیرهای داده و پشتیبان‌گیری

- دیتابیس: `data\\smartshelf.db`
- تصاویر آپلودشده: `data\\uploads`
- گزارش بک‌اند: `logs\\backend.log`
- نسخه‌های پشتیبان: `backups\\`

برای تهیه بکاپ سازگار از SQLite و تصاویر آپلودشده:

```powershell
.\scripts\backup_shelf.ps1
```

فایل بکاپ را فقط در فضای خصوصی و کنترل‌شده نگه دارید؛ ممکن است اطلاعات مشتری/فروشگاه در آن باشد.

## خاموش کردن دسترسی عمومی

برای غیرفعال کردن Funnel بدون حذف دیتابیس:

```powershell
.\scripts\disable_tailscale_funnel.ps1
```

## ملاحظات امنیتی و عملیاتی

- Funnel آدرس سرویس را در اینترنت عمومی قابل دسترس می‌کند؛ آن را محرمانه فرض نکنید. کنترل دسترسی باید با PIN مدیر، توکن‌های کوتاه‌عمر/جفت‌شده و بررسی‌های سمت سرور انجام شود.
- فریم خام دوربین در حافظه پردازش می‌شود و نباید روی دیسک ذخیره شود.
- هیچ سرویس ntfy، PeerJS یا STUN عمومی برای انتقال فریم/رویداد در مسیر عملیاتی استفاده نمی‌شود.
- Funnel دارای محدودیت پهنای‌باند است؛ نرخ/اندازه فریم را با تبلت واقعی آزمایش کنید. اگر WSS یا throughput پایدار نبود، قبل از فعال‌سازی فروش باید مشکل شبکه حل شود.
- لپ‌تاپ خاموش، Sleep، قطعی برق یا اینترنت یعنی بک‌اند و دوربین آفلاین می‌شوند. در زمان آفلاین بودن، خرید خودکار نباید ثبت شود.
- `STORE_OPEN=false` عمداً باقی می‌ماند. محصول اولیه «دلستر هی‌جو هلو» غیرفعال و قیمت آن صفر است؛ مدیر باید قیمت واقعی و وضعیت فعال را خودش تعیین کند. دو جایگاه دیگر بدون محصول می‌مانند. تشخیص حضور محصول با شناسایی هویت محصول یکی نیست؛ مدل عمومی MobileNet همراه پروژه embedding اختصاصی و معتبر محصول نیست و شناسایی هویت در این بسته عمداً غیرفعال شده است. خرید خودکار تا اعتبارسنجی مدل و آزمون‌های واقعی ممنوع می‌ماند.
- در این مرحله هیچ تغییری در Vercel Production یا فروشگاه واقعی انجام نشده است.
