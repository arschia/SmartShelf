# تشخیص بطری در محیط‌های مختلف — نسخهٔ ۱٫۲٫۱

## تصمیم اجرایی

برای ارائه در کلاس‌های مختلف، تشخیص شیء در کل تصویر مناسب‌تر از مقایسهٔ تصویر قفسهٔ پر و خالی است. مدل آمادهٔ YOLO26n اکنون به صورت ONNX در بسته قرار دارد و روی CPU کامپیوتر Windows اجرا می‌شود. عکس، دوربین همین دستگاه و فریم تبلت جفت‌شده در صفحهٔ `/bottle` قابل آزمایش است. مدل هنگام شروع به اینترنت یا API احتیاج ندارد؛ برای دسترسی Vercel به کامپیوتر از راه Funnel اینترنت همچنان لازم است. صفحه و مدل را می‌توان از پنل محلی نیز اجرا کرد.

مدل عمومی کلاس «bottle» را پیدا می‌کند، نه برند یا طعم. نام هی‌جو فقط وقتی در خروجی اختصاصی ظاهر می‌شود که مدل دارای کلاس `heyjo_peach` نصب شود. تشخیص بطری، خالی بودن جایگاه، شناسایی محصول و رویداد برداشت یک مسئله نیستند. این آزمایشگاه هیچ تغییری در سبد، فاکتور یا موجودی ایجاد نمی‌کند. سیستم دو‌مرجعی قبلی همچنان کار جداگانهٔ خود را انجام می‌دهد.

## نتیجهٔ واقعی این نسخه

وزن آماده از انتشار رسمی Ultralytics دریافت شده است:

https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo26n.onnx

SHA256: `2e947b787d9e787b93a16772a5f55b1d4d8c4d86f53146149c5d6a642442d6f7`

خروجی: `[1,300,6]`، ورودی: RGB با ابعاد ۶۴۰×۶۴۰ و حفظ نسبت تصویر. مجوز وزن AGPL-3.0 است؛ مجوز منبع همراه بسته قرار دارد.

تمام ۴۲ عکس موجود در `model_training.zip` با آستانهٔ ۰٫۳۵ بررسی شدند. در ۳۹ عکس حداقل یک بطری پیدا شد. عکس خالی شمارهٔ ۳۹ بدون تشخیص بود. دو تصویر دارای محصول، شمارهٔ ۲۶ (از بالا) و ۲۹ (در دست با پوشیدگی)، تشخیص نداشتند. در بعضی عکس‌ها بطری‌های پس‌زمینه نیز پیدا می‌شوند. میانگین پردازش در محیط بررسی حدود ۵۱ میلی‌ثانیه بود؛ این نرخ فریم نهایی یا بنچمارک کامپیوتر کاربر نیست.

این نتیجه دقت برند، تعمیم به کلاس جدید، عملکرد ویدیو یا سنجش مستقل نیست. فقط رفتار مدل عمومی روی داده‌های موجود است. هیچ وزن شبکه‌ای در این نسخه با تصاویر هی‌جو بازآموزی نشده است. گزارش JSON آزمایش همراه این سند است.

## چرا وعدهٔ هر زاویه و هر شرایطی ممکن نیست؟

نمای کامل از بالا، تاری، فاصلهٔ زیاد، پوشیده شدن برچسب و ضدنور می‌توانند اطلاعات لازم را حذف کنند. دو محصول با بطری یکسان و برچسب پنهان ممکن است از نظر تصویر غیرقابل تمایز باشند. در این موارد باید خروجی نامشخص پذیرفته شود یا از بارکد/نشان کمکی استفاده شود؛ نباید نام طعم حدس زده شود.

## آموزش اختصاصی پیشنهادی

برای شروع عملی، هدف جمع‌آوری حدود ۳۰۰ تا ۵۰۰ عکس متنوع در دست‌کم ۵ محیط است؛ این تعداد پیشنهاد اجرایی است، تضمین دقت یا حداقل علمی ثابت نیست. بخش عمده از هی‌جو، بخشی از بطری‌های دیگر و طعم‌های مشابه و بخشی از صحنه‌های بدون بطری باشد. نمونه‌ها شامل روبه‌رو، پشت، کنار، بالا، خوابیده، چرخیده، دور/نزدیک، نور کم/زیاد، دست و پوشیدگی جزئی باشند. تغییر نور و چرخش مصنوعی، جای نمای واقعی پشت و بالای بطری را نمی‌گیرد. اگر مدل عمومی از زاویهٔ بالا جا می‌ماند، همان نمونه را دستی کادر بکشید؛ خروجی مدل عمومی نباید تنها منبع برچسب باشد.

۱. وارد `/bottle` شوید، عکس انتخاب کنید یا عکس دوربین بگیرید.
۲. برای هر بطری کادر دقیق بکشید و یکی از دو برچسب «هی‌جو هلو» و «بطری دیگر» را انتخاب کنید. تمام بطری‌های هر تصویر را برچسب بزنید. عکس بدون بطری را صریحاً منفی ثبت کنید.
۳. نام محیط واقعی را وارد کنید؛ محیط یکسان را به چند نام تبدیل نکنید. کادرها را بازبینی و تأیید کنید و نمونه را ذخیره کنید. تصاویر فقط با این عمل ذخیره می‌شوند؛ تشخیص عادی فریم‌ها را روی دیسک ذخیره نمی‌کند.
۴. از حداقل سه محیط خروجی مجموعه‌داده بگیرید. کل یک محیط فقط در یکی از بخش‌های آموزش، اعتبارسنجی یا آزمون قرار می‌گیرد. دو گروه کوچک‌تر برای آزمون و اعتبارسنجی و بقیه برای آموزش هستند. بهتر است حداقل سه محیط آموزش و دو محیط کنارگذاشته‌شده داشته باشید. برای هر بخش، نمونهٔ هدف، بطری دیگر و صحنهٔ بدون بطری لازم است.
۵. در Colab یا محیط آموزش Python 3.12 با GPU، `ai/train_bottle.py` را اجرا کنید. نصب Torch/Ultralytics در محیط سرویس Windows لازم نیست. فایل Notebook همراه، مسیر اجرا را آماده کرده است.
۶. اسکریپت ابتدا داده را بررسی می‌کند، از وزن آماده شروع می‌کند، مدل را با اعتبارسنجی انتخاب می‌کند و فقط در پایان آزمون محیط کنارگذاشته‌شده را اجرا می‌کند. خروجی `best.onnx` و `training_report.json` است. اگر بارها با دیدن نتیجهٔ test تنظیمات را تغییر دادید، یک محیط آزمون جدید کنار بگذارید.
۷. قبل از فعال‌سازی، خطای پذیرش آب/نوشابه یا طعم دیگر، جاافتادن هی‌جو، چند بطری، فریم‌های در دست، تغییر کلاس، بازتاب شیشه و نور متفاوت را بررسی کنید. فقط mAP کلی کافی نیست؛ گزارش جداگانهٔ کلاس هی‌جو و تصاویر خطا را ببینید.

## اجرای آموزش

```bash
pip install -r ai/requirements-bottle-training.txt
python ai/train_bottle.py --data /path/to/extracted-dataset --audit-only
python ai/train_bottle.py --data /path/to/extracted-dataset --device 0 --epochs 80
```

پس از بررسی نتایج، وزن اختصاصی را در `ai/models/heyjo_peach.onnx` کپی کنید. در `.env` فقط این تنظیم را اضافه یا تغییر دهید و سرویس را دوباره اجرا کنید:

```dotenv
BOTTLE_MODEL_PATH=ai/models/heyjo_peach.onnx
```

کلیدها، پین، آدرس Funnel و دیتابیس را تغییر ندهید. خروجی مدل باید نام کلاس‌های `heyjo_peach` و `other_bottle`، ورودی ثابت ۶۴۰ و batch=1 داشته باشد. نصب وزن اختصاصی به تنهایی به معنی تأیید علمی عملکرد نیست.

## مقایسه با Gemini و OpenAI

هر دو API ورودی تصویر دارند. Gemini خروجی کادر شیء هم دارد. می‌توان عکس محصول مرجع و عکس جدید را به API داد و هویت محتمل را پرسید؛ این کار fine-tuning روی داده‌های شما نیست. استفاده نیازمند دسترسی API و کلید معتبر در بک‌اند است و به شبکه، سهمیه، زمان پاسخ و خطای مدل وابسته خواهد بود. هیچ کلیدی نباید داخل JavaScript عمومی قرار بگیرد. برای این پروژه، تشخیص محلی و آموزش اختصاصی را مسیر اصلی انتخاب کردیم؛ بررسی چند عکس مبهم با API می‌تواند بعداً مقایسهٔ مکمل باشد. هیچ کلید/API ابری در این نسخه استفاده نشده است.

## اصلاح آزمایش زنده در ۱٫۲٫۱

گزینهٔ پیش‌فرض اکنون «دوربین همین دستگاه» است؛ از عکس زندهٔ همین مرورگر برای تشخیص استفاده می‌کند و جفت‌کردن تبلت لازم نیست. گزینهٔ «تبلت متصل» همچنان به بازبودن صفحهٔ /camera/ و ارسال فریم نیاز دارد. نبودن فریم یا قطع موقت شبکه باعث انتظار و تلاش مجدد می‌شود؛ تشخیص قبلی پاک می‌شود تا کادر قدیمی زنده تلقی نشود. توقف آزمایش، درخواست فعال را لغو می‌کند.

کادرکشی دستی به‌صورت پیش‌فرض خاموش است. با فعال‌کردن گزینهٔ آن، می‌توان دادهٔ آموزش را برچسب زد. تمام برچسب‌ها فارسی شده‌اند و کادر دستی تا پیش از تیک تأیید و ثبت نمونه، بررسی‌شده نامیده نمی‌شود. برای خود تشخیص، دکمهٔ «تشخیص این عکس» را بزنید.
