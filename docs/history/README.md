# SMARTSHELF — فروشگاه هوشمند بدون صندوق

SmartShelf یک سامانه قفسه هوشمند است که تصویر قفسه را از تبلت دریافت می‌کند، تغییر وضعیت جایگاه‌ها را تشخیص می‌دهد و در صورت اطمینان کافی، رویداد را به هسته مدیریت فروشگاه می‌فرستد.

## معماری انتشار

- **فرانت‌اند عمومی:** `https://shelf-ir.vercel.app`
- **بک‌اند و پردازش تصویر:** FastAPI روی رایانه یا Mini PC فروشگاه
- **اتصال عمومی بک‌اند:** تونل HTTPS/WSS از طریق Tailscale Funnel
- **دوربین:** مرورگر Chrome تبلت؛ ارسال فریم به بک‌اند از طریق WebSocket احراز هویت‌شده
- **دیتابیس:** SQLite محلی روی دستگاه میزبان بک‌اند
- **پردازش تصویر:** OpenCV و NumPy؛ فریم خام فقط در حافظه پردازش می‌شود و روی Vercel یا دیسک ذخیره نمی‌شود.

Vercel میزبان استاتیک فرانت‌اند است و جایگزین بک‌اند دائمی و WebSocket پردازش تصویر نیست. دوربین باید مستقیماً به آدرس WSS بک‌اند متصل شود.

## موتور تشخیص دو مرجعی

برای هر جایگاه دو مرجع لازم است:

1. تصویر همان جایگاه در حالت **محصول حاضر**
2. تصویر همان جایگاه در حالت **خالی**

موتور جدید از ویژگی‌های SIFT (و در نسخه‌های OpenCV فاقد SIFT از ORB) و تطبیق هندسی RANSAC استفاده می‌کند. محدوده ROI هر جایگاه قابل انتخاب است.

- ویژگی‌های تصویری مرجع در دیتابیس ذخیره می‌شوند.
- تصویر خام مرجع یا فریم زنده در دیتابیس ذخیره نمی‌شود.
- نتیجه فقط یکی از سه حالت `PRESENT`، `ABSENT` یا `UNKNOWN` است.
- اگر یک مرجع ناقص باشد یا اختلاف دو مرجع کافی نباشد، نتیجه `UNKNOWN` است.
- تأیید تغییر وضعیت در ماشین حالت زمانی انجام می‌شود؛ فریم نامشخص، پیوستگی زمان تأیید را قطع می‌کند.
- آزمایش دستی صفحه کالیبراسیون سبد مشتری را تغییر نمی‌دهد؛ جریان زنده بک‌اند پس از تأیید پایدار تغییر، رویداد را به هسته اصلی می‌فرستد.

## تشخیص حضور با شناسایی هویت محصول فرق دارد

تشخیص دو مرجعی فقط تعیین می‌کند محصول از جایگاه برداشته شده یا در آن حضور دارد. شناسایی نام/شناسه محصول مرحله جداگانه‌ای است که از موتور MobileNet و داده‌های کاتالوگ استفاده می‌کند.

در بسته Windows Local، شناسایی هویت محصول عمداً غیرفعال است؛ مدل عمومی MobileNet همراه پروژه embedding اختصاصی و معتبر محصول محسوب نمی‌شود. تا زمان آموزش/اعتبارسنجی مدل مناسب، فقط حضور/خالی بودن دو‌مرجعی استفاده می‌شود و `STORE_OPEN=false` باقی می‌ماند.

آخرین ارزیابی موجود در فایل پروژه روی ۲۰ نمونه، دقت Top-1 برابر ۵۰٪ را گزارش کرده است. این حجم داده و این دقت برای شارژ خودکار و قطعی مشتری کافی نیست. پیش از فعال‌سازی فروش واقعی باید برای هر محصول تصاویر واقعی از زاویه‌ها، نورها و شرایط قفسه جمع‌آوری و ارزیابی مستقل انجام شود. تا آن زمان رویدادهای هویت نامطمئن باید بازبینی شوند.

## نصب بک‌اند در Windows

برای مسیر منتخب، فقط راهنمای [Windows Local + Tailscale Funnel](docs/WINDOWS_LOCAL_DEPLOY_FA.md) و اسکریپت `scripts/install_windows_local.ps1` را دنبال کنید. این اسکریپت Python 3.14، محیط مجازی، وابستگی‌ها، `.env` خصوصی و پوشه‌های پایدار `data/` را آماده می‌کند. بک‌اند از طریق `scripts/start_backend.ps1` فقط روی `127.0.0.1:8000` اجرا می‌شود.

**پورت 8000 را روی روتر/مودم یا Windows Firewall به اینترنت باز نکنید.** برای دسترسی عمومی از Tailscale Funnel استفاده کنید. تنظیم `PUBLIC_BASE_URL` پس از دریافت URL واقعی Funnel در `.env` نوشته می‌شود؛ سپس backend باید Restart شود.

## کالیبراسیون و راه‌اندازی دوربین

1. فرانت‌اند را روی `https://shelf-ir.vercel.app` باز کنید.
2. آدرس HTTPS بک‌اند را در تنظیمات سرور وارد کنید.
3. در پنل مدیریت، از بخش دستگاه‌ها کد جفت‌سازی دوربین را بسازید.
4. تبلت را به صفحه `https://shelf-ir.vercel.app/camera/` ببرید، دسترسی دوربین پشت را بدهید و کد جفت‌سازی را وارد کنید.
5. وضعیت اتصال باید پس از برقراری WSS از آفلاین به آنلاین تغییر کند.
6. در پنل مدیریت، تب «تشخیص حضور و شناسایی محصول» را باز کنید.
7. جایگاه را انتخاب کنید؛ یک مرجع با محصول حاضر و یک مرجع از همان زاویه با جایگاه خالی ثبت کنید.
8. ROI را تا حد امکان فقط دور محصول و محدوده لازم انتخاب کنید.
9. کالیبراسیون را ذخیره کنید و حالت حاضر، خالی و نامشخص را با فریم زنده آزمایش کنید.

## مسیرهای اصلی

- صفحه اصلی: `/`
- پنل مدیریت: `/admin/`
- حسگر دوربین تبلت: `/camera/`
- صفحه مشتری: `/customer/`
- ابزار کالیبراسیون دو مرجعی (از پنل مدیریت): `/presence?embed=admin`

## امنیت و حریم خصوصی

- ارتباط دوربین فقط از طریق توکن دستگاه جفت‌شده و WSS به بک‌اند انجام می‌شود.
- رویدادهای سبد خرید فقط از بک‌اند احراز هویت‌شده پذیرفته می‌شوند.
- ارتباط عمومی ntfy و مسیرهای شبیه‌سازی احراز هویت/خرید در فرانت‌اند عملیاتی حذف شده‌اند.
- تصاویر خام دوربین در حافظه پردازش می‌شوند؛ حجم و ابعاد فریم ورودی محدود شده است.
- `.env`، دیتابیس، کلیدهای خصوصی، گواهی‌ها و فایل‌های پشتیبان را در مخزن عمومی یا بسته انتشار قرار ندهید.
- اگر فایل‌های محرمانه قبلاً در مخزن عمومی قرار گرفته‌اند، کلیدها و PINها را تعویض کنید.

## بررسی پیش از انتشار

```powershell
python scripts/predeploy_check.py
python -m compileall backend
```

بررسی‌های JavaScript:

```powershell
node --check frontend/admin/app.js
node --check frontend/camera/app.js
node --check frontend/customer/app.js
```

برای انتشار استاتیک روی Vercel، Root Directory را `frontend` قرار دهید. هیچ تابع serverless برای دریافت فریم دوربین روی Vercel تعریف نکنید.

## محدودیت‌های فعلی

- بک‌اند باید روی دستگاه روشن و متصل به تونل باقی بماند.
- توکن‌های جفت‌سازی دوربین در حافظه بک‌اند نگهداری می‌شوند؛ پس از راه‌اندازی مجدد بک‌اند ممکن است نیاز به جفت‌سازی مجدد باشد.
- تشخیص حضور/خالی بودن از شناسایی هویت محصول مستقل است.
- تا زمان ارزیابی مجدد مدل شناسایی محصول با داده‌های واقعی کافی، خرید خودکار را بدون کنترل انسانی فعال نکنید.
