# وضعیت اصلاح جفت‌سازی و تصاویر مرجع — 2026-11-05

## اصلاح اتصال تبلت
- عبارت JavaScript قبلی به‌جای شش رقم، الگوی دارای بک‌اسلش را بررسی می‌کرد؛ حتی کد انگلیسی صحیح رد می‌شد.
- ارقام فارسی و عربی، فاصله و علامت‌های نامرئی جهت متن پیش از بررسی شش رقم نرمال می‌شوند؛ حروف و طول نامعتبر همچنان رد می‌شوند.
- پنل فقط کد صادرشده توسط بک‌اند را نشان می‌دهد؛ تولید کد تصادفی هنگام خطای شبکه/احراز هویت حذف شد.
- فرم ورود نیز پین ۱۸ کاراکتری نصب‌کننده را می‌پذیرد.
- ۱۳۲ تست بک‌اند موفق؛ اجرای handlerهای واقعی camera/admin در Node با ورودی انگلیسی، فارسی، عربی، فاصله/جهت متن و خطای شبکه موفق.
- تغییرهای نرمال‌سازی سمت Python در سورس بسته آماده‌اند؛ ارسال نرمال‌شدهٔ فرانت‌اند با بک‌اند نصب‌شدهٔ فعلی سازگار است.

## آیا همهٔ تصاویر آموزش داده شده‌اند؟
خیر. در این مرحله هیچ آموزش یا fine-tune شبکهٔ عصبی روی همهٔ تصاویر مرجع اجرا نشده است.
نسخهٔ فعلی از ویژگی‌های SIFT/ORB و RANSAC برای دو مرجع حاضر/خالی هر جایگاه استفاده می‌کند؛ افزودن مرجع، آموزش شبکهٔ عصبی محسوب نمی‌شود.
مدل عمومی MobileNet همراه سورس، مدل اختصاصی آموزش‌دیدهٔ این محصول نیست؛ شناسایی هویت محصول در تنظیم نصب فعلی غیرفعال است.
در بررسی API زندهٔ /api/presence هر سه جایگاه calibrated=false داشتند. این نتیجه دربارهٔ کالیبراسیون دو‌مرجعی معتبر فعلی است، نه ادعای نبود هر نوع دادهٔ قدیمی.

## مقایسه با نمونهٔ قبلی
نسخهٔ صفحهٔ shelf-arschias-projects.vercel.app/presence و بستهٔ SMARTSHELF_two_reference_presence_v2.zip بررسی شدند.
API نسخهٔ مستقر از ابزار Vercel به‌صورت ناقص و کوتاه‌شده برگشت؛ برای بررسی کامل الگوریتم از سورس موجود در بستهٔ v2 استفاده شد. مطابقت کامل بایت‌به‌بایت API مستقر ادعا نمی‌شود.
| مورد | بستهٔ نمونهٔ v2 | موتور یکپارچهٔ فعلی |
|---|---|---|
| ورودی مرجع | یک مرجع پر + یک مرجع خالی | یک مرجع پر + یک مرجع خالی در هر Zone |
| هم‌ترازی | ابتدا صحنهٔ کامل با Homography، سپس تمرکز روی ROI و نقاط پس‌زمینه | استخراج و تطبیق ویژگی‌های محدودهٔ هر Zone |
| نور | محاسبهٔ جابه‌جایی روشنایی و خطای پس‌زمینه | امتیاز تطبیق ویژگی‌ها و حاشیهٔ تصمیم |
| آموزش شبکه | وجود ندارد | در این کار انجام نشده |
| تأیید کیفیت روی قفسهٔ واقعی | به آزمایش کاربر وابسته است | هنوز به آزمایش واقعی تبلت و مرجع‌های همان قفسه نیاز دارد |

این دو پیاده‌سازی دقیقاً یکسان نیستند. اختلاف روش می‌تواند اختلاف رفتار را توضیح دهد، اما برتری یکی بدون آزمون یکسان روی تصاویر واقعی تأیید نشده است.
موتور تشخیص در این اصلاحیه جایگزین نشده؛ تغییرهای این اصلاحیه مربوط به اتصال و اعتبارسنجی کد است.
