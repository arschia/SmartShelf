# اصلاح راه‌اندازی دوربین — نسخهٔ ۱٫۳٫۲

در صفحهٔ دوربین، بعد از موفقیت getUserMedia و شروع نمایش ویدیو، تابع حذف‌شدهٔ connectWebRTCStream فراخوانی می‌شد. خطای ReferenceError آن وارد همان catch عمومی می‌شد و به‌اشتباه پیام «مرورگر اجازهٔ دوربین نداده است» نمایش داده می‌شد. مجوز می‌توانست کاملاً معتبر باشد و با این حال پیام دیده شود.

این فراخوانی حذف شد. انتقال تصویر همان WSS/HTTPS نسخهٔ ۱٫۳٫۱ است و وابستگی به WebRTC ندارد. خطاهای مجوز، اشغال‌بودن دوربین، تنظیمات نامعتبر و پخش ویدیو جدا گزارش می‌شوند. توقف عمدی دوربین قبلی هنگام عوض‌کردن دوربین، خطای سخت‌افزار تلقی نمی‌شود. اگر مجوز دریافت شده ولی پخش خودکار آغاز نشود، دکمهٔ تلاش مجدد با همان stream و تعامل کاربر نمایش را شروع می‌کند. تنظیمات پشتیبانی‌نشده یک بار با دوربین پیش‌فرض ساده‌تر امتحان می‌شوند.

این اصلاح روی وب منتشر می‌شود و برای استفاده از صفحهٔ اصلی به نصب دوبارهٔ بک‌اند نیاز ندارد. روی تبلت، صفحه‌های دیگرِ استفاده‌کننده از دوربین را ببندید و این لینک را مستقیم در Chrome باز کنید:

https://shelf-ir.vercel.app/camera/?v=1.3.2

اگر پیام ادامه داشت، کد خطایی که زیر آن ظاهر می‌شود علت دقیق‌تری می‌دهد: NotReadableError برای اشغال/خطای دستگاه، NotAllowedError برای انسداد دسترسی، یا پیام جداگانهٔ پخش تصویر. تغییر Chrome Flags برای این باگ لازم نیست.

تست startup، کد واقعی صفحه را با مرزهای کنترل‌شدهٔ دوربین و DOM اجرا می‌کند: موفقیت با مجوز معتبر، تغییر عمدی دوربین، دستگاه اشغال، مجوز ردشده، خطای autoplay و تلاش مجدد با همان stream، fallback تنظیمات و تشخیص HTTPS بررسی شدند. تست‌های انتقال WSS/HTTPS و جفت‌سازی قبلی نیز موفق ماندند. این‌ها آزمون روی سخت‌افزار تبلت کاربر نیستند؛ بررسی فیزیکی پس از تازه‌سازی صفحه باقی است.
